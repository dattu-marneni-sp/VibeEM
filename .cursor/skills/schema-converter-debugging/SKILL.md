# Schema Converter Debugging

Use this workflow when `sailpoint/entity-live-dip` schema generation fails or CI reports autogenerated files are out of sync.

## Principle

Find which generator step failed before changing code. The schema converter has separate paths for source YAML, dbt model SQL, Airflow pipeline YAML, checkpoint config, and Soda checks.

## Fast Triage

Start in:

```bash
cd transformers/streaming/schema_converter
```

Run:

```bash
make debug
make autogen_all
```

If CI failed, reproduce the same validation from repo root:

```bash
./cicd/scripts/validate-autogen.sh
```

Then inspect:

```bash
git status
git diff
```

Generated changes mean the committed files are stale or the generator changed.

## Generator Map

The CLI entrypoint is `transformers/streaming/schema_converter/src/main.py`.

Commands map to these components:

- `make autogen_sources` -> `generate source-yml` -> `generators/source_yml.py`
- `make autogen_models` -> `generate dbt-model` -> `generators/dbt_model.py`
- `make autogen_pipelines` -> `generate pipeline` -> `generators/pipeline.py`
- `make autogen_checkpoints` -> `update` -> `util/checkpoint.py`
- `make autogen_soda_checks` -> `generate soda-checks` -> `generators/soda_checks.py`
- `make validate_soda_checks` -> `validate soda-checks` -> `validators/soda_checks.py`
- `compare` -> `util/schema_diff.py`

## Common Failures

### Schema Not Processed

Check:

- File is under `transformers/streaming/schema_converter/schemas`.
- File ends with `.json`.
- File does not end with `example.json`.
- File is not listed in `BLACKLIST` in the schema converter `Makefile`.

Run:

```bash
make debug
```

If the schema is intentionally custom, blacklist it and manage custom outputs manually.

### Invalid Or Unsupported Schema

Check the JSON parses and has expected top-level structure:

- `type: object`
- `properties`
- optional `$defs`
- optional `required`

Watch for:

- Unsupported `$ref` paths outside `#/$defs/...`.
- Deep recursive references. The resolver has recursion protection and may fall back to object handling.
- Complex object or array fields that simplify to `STRING` for source YAML and are cast to `VARIANT` or `ARRAY` in dbt.

### Missing Source YAML

Run:

```bash
make autogen_sources
```

Expected output:

`transformers/streaming/dbt/models/entity_live_tables/<table>/source.yml`

Check that the source has:

- `topic-pattern: ^<table>(_backfill)?$`
- `kafka_key`
- `headers`
- `hard_deleted`
- Kafka metadata fields

### Missing dbt Model

Run:

```bash
make autogen_models
```

Expected output:

`transformers/streaming/dbt/models/entity_live_tables/<table>/<table>.sql`

Check for:

- Snowflake connector config.
- `checkpoint_name` defaulting to `<table>_live`.
- `primary_key = 'KAFKA_KEY'`.
- `partition_by = 'TENANT_ID'`.
- Complex fields emitted as `` `FIELD::VARIANT` `` or `` `FIELD::ARRAY` ``.

### Missing Airflow Pipeline YAML

Run:

```bash
make autogen_pipelines
```

Expected output:

`pipelines/dags/entity_live_dip/entity_live_dags/<base_name>_template.yml`

Note: the pipeline generator derives `base_name` by removing `_v1` from the schema filename.

Check:

- `dag_id: sf_live_<schema_name>_{{ dag_label }}`
- `job_name: <schema_name>`
- `checkpoint_name: <schema_name>_live`
- `checkpoint_version: {{ <schema_name>_checkpoint_version }}`

### Missing Checkpoint Config

Run:

```bash
make autogen_checkpoints
```

Expected behavior:

- Adds `<schema_name>_checkpoint_version: v1` to environment config entries under `pipelines/dags/entity_live_dip/entity_live_dags/configs/**`.

Check:

- Config files are valid YAML.
- Entries have `dag_label`; the updater only appends checkpoint keys to mappings with `dag_label`.
- The schema is not blacklisted.

### Soda Validation Fails

`make autogen_all` validates Soda checks but does not generate them.

If validation says checks are missing or stale, run:

```bash
make autogen_soda_checks
make autogen_all
```

Check:

- Output exists under `transformers/fire/src/soda_quality_checks/auto_generated_checks`.
- `_manifest.json` was updated.
- The schema is not skipped by naming rules such as `_example`, `_dedup`, `_aggregate`, `_flattened`, `_intermediate`, or `_tmp`.
- AWS Bedrock credentials are available when generating checks locally.

### CI Reports Autogenerated Files Out Of Sync

CI runs:

```bash
cd transformers/streaming/schema_converter
make autogen_all
git status --porcelain
```

Fix locally:

```bash
cd transformers/streaming/schema_converter
make autogen_soda_checks
make autogen_all
cd ../../../
git status
git diff
```

Commit all intentional generated changes.

## Debugging Order

Use this order unless the error clearly points elsewhere:

1. Reproduce locally with `./cicd/scripts/validate-autogen.sh`.
2. Identify the first failing make target.
3. Confirm the schema is valid JSON and not skipped.
4. Run the specific failing target only.
5. Inspect generated output paths and `git diff`.
6. Fix the schema or generator, not generated files, unless the schema is explicitly custom/blacklisted.
7. Rerun `make autogen_soda_checks` if schemas changed.
8. Rerun `make autogen_all`.

## Findings Format

Report:

- Failing command and first error.
- Affected schema and whether it is skipped or blacklisted.
- Missing or stale generated outputs.
- Root cause.
- Exact local fix command.
- Files that should be committed.
