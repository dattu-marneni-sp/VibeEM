# How To Add A New Entity Live Table

This guide documents the verified workflow for adding a new schema-backed live table in `sailpoint/entity-live-dip`.

## Overview

`entity-live-dip` is schema-driven. A JSON schema under `transformers/streaming/schema_converter/schemas` is the source of truth. The schema converter generates dbt source YAML, dbt model SQL, Airflow/Flink DAG templates, checkpoint config entries, and Soda data quality checks.

## Prerequisites

- Local clone of `sailpoint/entity-live-dip`
- Python, pip, and virtualenv support
- SailPoint JFrog/pip access for internal dependencies
- AWS Bedrock access if generating Soda checks locally

## Step 1: Add The Schema

Create a JSON schema:

```text
transformers/streaming/schema_converter/schemas/<table_name>.json
```

Example:

```text
transformers/streaming/schema_converter/schemas/my_entity_v1.json
```

The schema filename becomes the table/entity name. Do not use `_example.json` for a deployable schema.

## Step 2: Initialize The Schema Converter

From the `entity-live-dip` repo:

```bash
cd transformers/streaming/schema_converter
make init
```

This creates `venv` and installs dependencies from `requirements.txt`.

## Step 3: Generate Soda Checks

For a new or changed schema, run:

```bash
make autogen_soda_checks
```

This writes checks to:

```text
transformers/fire/src/soda_quality_checks/auto_generated_checks/<table_name>.yml
```

It also updates the Soda manifest. This step may require AWS Bedrock access.

## Step 4: Generate And Validate Outputs

Run:

```bash
make autogen_all
```

This runs:

- `autogen_sources`
- `autogen_models`
- `autogen_pipelines`
- `autogen_checkpoints`
- `validate_soda_checks`

Important: `make autogen_all` validates Soda checks, but it does not generate them.

## Generated Files

For schema:

```text
my_entity_v1.json
```

expect:

```text
transformers/streaming/dbt/models/entity_live_tables/my_entity_v1/source.yml
transformers/streaming/dbt/models/entity_live_tables/my_entity_v1/my_entity_v1.sql
pipelines/dags/entity_live_dip/entity_live_dags/my_entity_template.yml
pipelines/dags/entity_live_dip/entity_live_dags/configs/**
transformers/fire/src/soda_quality_checks/auto_generated_checks/my_entity_v1.yml
```

Note: the pipeline generator removes `_v1` from the template filename. `my_entity_v1.json` generates `my_entity_template.yml`, not `my_entity_v1_template.yml`.

## Step 5: Review The Generated Files

Before opening a PR, verify:

- Schema fields, required fields, and types match the Kafka payload.
- Object and array fields map intentionally to Snowflake `VARIANT` or `ARRAY`.
- The dbt model extracts `POD`, `ORG`, `TENANT_ID`, and `EVENT_ID` from headers.
- The dbt model uses the expected primary key, usually `KAFKA_KEY`.
- The DAG template has the expected `dag_id`, `job_name`, `checkpoint_name`, and checkpoint version variable.
- Checkpoint config entries were added for target environments.
- Soda checks exist and are not stale for the schema.
- Generated files were not hand-edited unless the schema is intentionally blacklisted in the schema converter Makefile.

## Step 6: Inspect And Commit

Return to the repo root:

```bash
cd ../../../
git status
git diff
```

Commit the schema and generated files together.

## Pre-commit Behavior

The repo pre-commit hook runs:

```bash
make -C transformers/streaming/schema_converter autogen_all
```

Install hooks with:

```bash
pip install pre-commit
pre-commit install
```

Bypassing hooks can leave generated files stale and block the PR in CI.

## CI Behavior

The GitHub Action `.github/workflows/validate-autogen.yml` runs on relevant PR changes. It:

1. Installs schema converter dependencies.
2. Runs `make autogen_all`.
3. Fails if `git status --porcelain` shows generated changes.

CI is checking that regeneration from the committed schema leaves the repo clean.

## Fixing CI Autogen Failures

If CI reports autogenerated files are out of sync, run:

```bash
cd transformers/streaming/schema_converter
make autogen_soda_checks
make autogen_all
cd ../../../
git status
git diff
```

Then commit the regenerated files.

## Safe Command Sequence

For a new or changed schema, the safest local sequence is:

```bash
cd transformers/streaming/schema_converter
make init
make autogen_soda_checks
make autogen_all
cd ../../../
git status
git diff
```
